## Safe VPS Deployment

Wait until jobs and worker leases are inactive. Do not start/resume jobs while
deploying. Run this complete block; Ctrl+C only ends the log viewer.

```bash
(
set -Eeuo pipefail
cd /opt/translate
git fetch origin main --tags
git show v20.5:scripts/deploy_tarjomeh_v205.sh > /root/deploy_tarjomeh_v205.sh
chmod 700 /root/deploy_tarjomeh_v205.sh
LOG=/root/deploy_tarjomeh_v205.log
nohup bash /root/deploy_tarjomeh_v205.sh > "$LOG" 2>&1 < /dev/null &
echo "Deployment PID: $!"
tail --retry -F "$LOG"
)
```

Require `Deployment v20.5 completed. Running 9router was unchanged.` before
starting jobs. Inspect the final log: successful nohup launch is not deployment
success. The script checks active jobs/leases twice, preserves config/glossary,
uses a WAL-consistent SQLite backup, and restores the gzip snapshot in isolation
with hash and integrity verification. Existing snapshots are not overwritten.

Cleanup targets only verified unused Tarjomeh resources. No global Docker prune,
router image/container/data/backup removal or host-log purge. Running 9router ID,
image, start time and mounts are compared before/after. Safe disk insufficient
means STOP; never bypass the backup/build reserve or delete 9router rollback
resources to force a deploy. The Tarjomeh rollback image is kept until validation;
the inherited small-disk policy removes it after success. Keep the fresh backup.

probes true and healthy Docker status. A release string alone is insufficient.

## Fresh Run And Full Audit

Use matched settings/source for a review-off control and an opt-in fresh job.
Approve meanings and occurrences explicitly; keep automatic enforcement OFF.
For the first comparison pause at the same chapter checkpoint. Existing UI URL
and authentication remain unchanged. The new-job term-review checkbox stays
unchecked by default; enabling it adds only the already implemented early wait.

After that job pauses or finishes, set its actual ID and run both audits:

```bash
(
cd /opt/translate || exit 1
JOB=YOUR_NEW_JOB_ID
REPORT_RC=0
bash scripts/audit_tarjomeh_v205_reports.sh "$JOB" || REPORT_RC=$?
COMPANION_RC=0
bash scripts/audit_tarjomeh_v205_companion.sh "$JOB" || COMPANION_RC=$?
printf 'Reports exit=%s Companion exit=%s\n' "$REPORT_RC" "$COMPANION_RC"
[ "$REPORT_RC" -eq 0 ] && [ "$COMPANION_RC" -eq 0 ]
)
```

Both scripts run even if the first fails. A hard FAIL exits nonzero; REVIEW is
not clean semantic certification. Reports include active/lifetime attempts,
retries, successful served models, failures, tokens and time per operation;
conditional extra work; all four memories/style and research; source/canonical
and delivered-text identity. JSON helper attempts and invalid structured-response
events are distinct from provider failures. No audit can mechanically certify
all Persian semantics or every full-book step from a short checkpoint.

The `v205_quality_safeguards` section now exposes `prompt_component_evidence`
entries with complete saved text/hash/character counts, or explicit withheld
reasons. Storage limits remain 128 complete entries of at most 12,000 characters;
actual prompts are not capped. Invalid entries/hashes cause FAIL. Possible secrets
are withheld, never redacted and mislabelled exact. Legacy missing context is
unavailable, not reconstructed. `term_sample_coverage` reports exact lexical sample
presence and option availability, not sense accuracy or family completeness.

Send the matching job's DOCX, QA TXT, memory JSON/TXT, companion JSON/TXT,
server-wide companion TXT and deployment log. Recheck the old blocked job
separately; a fresh job cannot prove its recovery. Selected-chapter occurrence
review, individual ticks, bilingual export and restart need their own evidence.

## Offline Fluency Trial

The existing zero-call dry run is still available:

```bash
JOB=bd26593075d6
OUT="/app/jobs/uploads/${JOB}_v205_fluency_trial_$(date +%Y%m%d-%H%M%S)"
docker exec translate_tarjomeh_1 env PYTHONIOENCODING=utf-8 python -m tarjomeh.quality.fluency_trial "$JOB" --out "$OUT"
```

Do not add `--execute` while production jobs or leases are active. Explicit
execution is optional, billed offline work. See V20.4_RELEASE.md for the existing
execution command/routing and partial replay limits. v20.5 adds general lexical-
role and habitual/completed-aspect guidance only in that isolated process and
records the exact-text deterministic baseline. Production prompts are untouched.

All three reviewer arms receive the same disclosed reconstructed empty review
context. Saved translator components do not prove the historical critic context.
Compare both ordinary arms and all existing same-text findings. Review outcomes
manually; require at least two real unique catches and precision >=80%, counting
uncertain/unsupported findings. Synthetic positives earn no improvement credit.
Model mismatch is inconclusive and requires an explicit bounded rerun of that
chunk on matching routing; there is no automatic model switch or endless retry.
Partial refiner/integrity/R109 checks are not full glossary/DOCX/memory admission.
No result enables the reviewer, expands production budgets or certifies readiness.
