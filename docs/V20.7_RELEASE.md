# v20.7: Source-proven notes and independent-edit admission

This release fixes R159/T59, R160/T60 and R161/T61. It does not add a reviewer,
change model prompts, raise call allowances, lower quality/style thresholds,
remove a memory layer or make research terminology authoritative. It is ready
for a fresh checkpoint test after local gates; academic quality remains REVIEW.

## Changes

- Plain, Unicode and styled representations of the same physical note count once.
  Two physical cues count twice. Word-before-dash duplicates require a unique
  retained source-original anchor to repair; source numerals and uncertain
  locations are not guessed away. DOCX read-back checks actual run styling.
- An identical, located terminology REVIEW in a byte-identical paragraph can be
  carried through an independent repair elsewhere. It is not cleared. Final
  book-term compliance still withholds authority using the existing policy.
  Changed/unlocated reviews and new violations continue blocking candidates.
- Current approvals, occurrence ticks, scopes and legacy counters have separate
  labels. Note evidence is additive, hash-bound and report-only for old runs.

The old saved job is not silently rewritten. A reviewer proposal or a high score
is not proof that wording is accurate. Experimental guidance remains OFF.

## VPS deployment

Run this entire block in PuTTY. It runs in a subshell so a stopped precheck does
not close your login shell. Do not start jobs during deployment. After completion,
Ctrl+C stops only the log viewer.

```bash
(
set -Eeuo pipefail
cd /opt/translate
git fetch origin main --tags
git show v20.7:scripts/deploy_tarjomeh_v207.sh > /root/deploy_tarjomeh_v207.sh
chmod 700 /root/deploy_tarjomeh_v207.sh
bash -n /root/deploy_tarjomeh_v207.sh
LOG="/root/deploy_tarjomeh_v207_$(date +%Y%m%d-%H%M%S).log"
nohup bash /root/deploy_tarjomeh_v207.sh > "$LOG" 2>&1 < /dev/null &
echo "Deployment PID: $!"
echo "Log: $LOG"
tail --retry -F "$LOG"
)
```

The script checks jobs and worker leases, snapshots SQLite consistently including
WAL, verifies restoration and integrity, preserves local glossary/settings, and
builds on the exact previous image. It removes only verified unused Tarjomeh
resources, retains the current rollback image, and stops if safe space is
insufficient. It neither prunes Docker globally nor removes old/running 9router
containers, images or data. Router ID/image/start time/mounts must remain equal.

Installed release, revision, image Git label and behavior are checked by deploy.
To repeat the runtime verification:

```bash
docker exec translate_tarjomeh_1 tarjomeh capabilities --verify --json
docker exec translate_tarjomeh_1 python -c 'from tarjomeh.runtime import RUNTIME_RELEASE, RUNTIME_REVISION; assert (RUNTIME_RELEASE, RUNTIME_REVISION) == ("v20.7", 1); print(RUNTIME_RELEASE, RUNTIME_REVISION)'
```

## Fresh checkpoint and full audit

Use the existing models/routes, critique, integrity and glossary gates. Keep
unapproved-term enforcement off and experimental guidance off. Stop at the same
chapter-7 checkpoint for comparison. Approve terminology only after inspecting
its meaning and permitted occurrences; record any changed settings/approvals.

Run both collectors after the checkpoint, replacing the placeholder once:

```bash
(
cd /opt/translate || exit 1
JOB=YOUR_NEW_JOB_ID
bash scripts/audit_tarjomeh_v207_reports.sh "$JOB"
REPORT_RC=$?
bash scripts/audit_tarjomeh_v207_companion.sh "$JOB"
COMPANION_RC=$?
printf 'Report exit: %s; companion exit: %s\n' "$REPORT_RC" "$COMPANION_RC"
test "$REPORT_RC" -eq 0 && test "$COMPANION_RC" -eq 0
)
```

The collectors preserve active/lifetime accounting, requested and returned models,
transport/schema failures, retries, stages, extra-pass outcomes, all four memories,
style eligibility, research, approved scopes, hashes and checkpoint/export evidence.
A hard failure exits nonzero; REVIEW is not publication certification.

From `/opt/translate/jobs/uploads`, provide the new job's DOCX, QA report,
`JOB_v207_memory_audit.json/.txt`, `JOB_v207_companion_audit.json/.txt` and
`tarjomeh_v207_companion_audit.txt`, plus the deployment log above. Semantic
source-vs-DOCX review is still required before continuing the whole book.
