# v20.4 Release And Verification

## Scope

Production stage order and the four memories are unchanged. No unconditional
reviewer, new refiner budget, hard prompt cap, global term replacement, automatic
approval, book-specific rule, prose-year conversion or table reconstruction ships.
The focused attachment reviewer remains OFF. Current critic/translator/refiner
and summary prompts are unchanged pending a source-grounded offline trial and
human approval. Local tests cannot certify academic Persian or full-book quality.

## Deploy

Wait for jobs to pause or finish, and do not start/resume any job during deployment.
Run the complete block below on the VPS. Ctrl+C stops the log viewer only; the
background deployment continues. Read its final success line before starting jobs.

```bash
(
set -Eeuo pipefail
cd /opt/translate
git fetch origin main --tags
git show v20.4:scripts/deploy_tarjomeh_v204.sh > /root/deploy_tarjomeh_v204.sh
chmod 700 /root/deploy_tarjomeh_v204.sh
LOG=/root/deploy_tarjomeh_v204.log
nohup bash /root/deploy_tarjomeh_v204.sh > "$LOG" 2>&1 < /dev/null &
echo "Deployment PID: $!"
tail --retry -F "$LOG"
)
```

The script refuses other tracked modifications while preserving the permitted
local glossary byte-for-byte. It checks active statuses AND worker leases twice.
Its backup includes committed SQLite WAL data, passes an integrity check, and is
compressed, restored to a new isolated file, hash-compared and integrity-checked
again. No existing snapshot is overwritten and the live database is never
restored as a test. Peak backup space and the 350 MB build reserve remain guarded.

Only container-unreferenced Tarjomeh images and verified old Tarjomeh backups are
cleanup candidates. There is no global Docker prune, host-log purge, or 9router
image/container/data cleanup. Insufficient safe space stops deployment. Running
9router ID, image, start time and mounts are compared before and after. Keep the
fresh Tarjomeh backup. The existing small-disk policy removes the old Tarjomeh
image only after successful validation; rollback thereafter requires redeploying
the previous Git tag. Never delete 9router rollback data to bypass this script.

## Fresh Checkpoint And Audit

Use the same translation settings as the control run. Test review-off and opt-in
reviewed-occurrence jobs separately; approving a proposal is not approving every
occurrence or proving its Persian sense. Keep automatic enforcement off. For the
first comparison pause at a chapter checkpoint. Audit the previously blocked job
separately; do not confuse a new job's DOCX with its old reports.

```bash
cd /opt/translate
JOB=YOUR_NEW_JOB_ID
REPORT_RC=0
bash scripts/audit_tarjomeh_v204_reports.sh "$JOB" || REPORT_RC=$?
COMPANION_RC=0
bash scripts/audit_tarjomeh_v204_companion.sh "$JOB" || COMPANION_RC=$?
printf 'Reports exit=%s Companion exit=%s\n' "$REPORT_RC" "$COMPANION_RC"
```

Both scripts run even if the first detects a hard failure. FAIL exits nonzero and
must not be interpreted as PASS. REVIEW is not clean semantic certification.
Send the job's QA report, memory JSON/TXT, companion JSON/TXT, DOCX, server-wide
companion TXT and deployment log. Audits include all four memories, style,
research, canonical/export evidence and active/lifetime LLM attempts, served
models, retries, failures, tokens and time, including the existing extra pass.
Invalid structured-response repairs are distinct from provider/request failures.

The v204 safeguard section re-evaluates occurrence counts, style eligibility and
punctuation without rewriting stored historical quality decisions. Exact prompt
context absent from an older job is reported unavailable. Component storage is
bounded to 128 distinct complete entries of up to 12,000 characters each per job;
larger contexts are hashed and unavailable, never silently clipped or excluded
from the actual translation prompt. This storage bound does not change call size.

## Optional Fluency Experiment

Production guidance and budgets remain unchanged. The isolated harness compares
two ordinary critiques against proposed source-first fluency guidance on identical
saved text/context, followed optionally by one refiner trial and renewed critique,
integrity and R109 checks. It writes only a separate output directory, not job
records, memory, status or production configuration. It loads the saved job's
critic route with current credentials, including the configured 9router endpoint;
it does not switch to a public OpenRouter endpoint or print keys.

First perform a zero-call dry run (indices are database indices, not UI numbers):

```bash
JOB=e2f217b8b299
OUT="/app/jobs/uploads/${JOB}_v204_fluency_trial_$(date +%Y%m%d-%H%M%S)"
docker exec translate_tarjomeh_1 python -m tarjomeh.quality.fluency_trial "$JOB" --indices 9 13 --out "$OUT"
```

When idle, an explicit execution is:

```bash
docker exec translate_tarjomeh_1 env PYTHONIOENCODING=utf-8 python -m tarjomeh.quality.fluency_trial "$JOB" --indices 9 13 --out "$OUT" --execute --with-refinement
```

Allow for model latency. Two saved chunks plus three controls incur 15 ordinary/
experimental critique operations, plus at most one refinement and renewed critique
per eligible case, plus the saved bounded retry/JSON-repair policy. This trial is
additional OFFLINE cost, not new production calls. It records physical attempts,
models, elapsed time and tokens. A matched model is required; rerun inconclusive
chunks explicitly rather than silently changing model or retry policy.

All calls use the same disclosed reconstructed empty review context. This is not
a replay of missing historical prompts. Existing QA/readability/structure findings
on the exact target belong in the baseline. Controls must remain quiet; synthetic
positives test sensitivity only and earn no improvement credit. Unsupported or
uncertain findings count against precision. A human must verify source heads,
dependencies, scope, counts, modality, terminology and every proposed edit. No
model judge decides correctness. Full glossary, canonical/DOCX and memory gates
are not replayed, so a passing partial check is never production admission.

Review `fluency_trial.json` before authorizing any production prompt revision.
No trial result, clean checkpoint or test suite automatically enables guidance or
marks the release production-ready.
