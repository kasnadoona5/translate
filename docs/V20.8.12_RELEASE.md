# v20.8.12: Numeric Announcement Boundaries

The structural count checker now treats contiguous dotted and decimal numbers
as whole spans. A table identifier such as `2.2` or `2.2.1`, or a decimal such
as `2.5`, cannot supply a standalone cardinal from its last digit. ASCII,
Persian and Arabic-Indic digits are supported with `.` and U+066B separators.

The shared word tokenizer and translated text are unchanged. Ordinary quantity
evidence remains active, including a real count following an identifier. Genuine
source-count mismatches still invoke the existing bounded repair/admission
policy; this is not a blanket structure exemption for tables or headings.

The `numeric_announcement_boundaries` capability has a pure behavior probe for
false-positive suppression and genuine mismatch detection. The versioned deploy
and both audit collectors require it alongside all previous safeguards.

No production prompt, model, stage order, memory policy, style rule, glossary
scope, refiner veto, call budget or DOCX identity requirement is changed. The
patch adds no production LLM call and no book-specific rule. Runtime probes and
offline tests are local verification, not certification of semantic accuracy.

Deployment retains consistent SQLite backup/restore checks, exact Docker
revision and health checks, rollback, and guarded Tarjomeh-only cleanup. It
refuses active jobs/leases and unsafe free-space conditions. It does not touch
9router or prune shared Docker resources.

Do not interrupt a running translation to install this release. After deployment,
resume the existing job only if it remains paused; completed chunks need no
retranslation merely to validate the detector. Send the checkpoint DOCX, both
audit sets and full deployment log for live validation. Unexplained rendered
text changes and genuinely altered quantities must still block publication.
